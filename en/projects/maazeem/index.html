The story

MAAZEEM started from real demand: people and companies working in invitations and events were asking for systems to manage guests, sending and attendance — and building a separate system for each client was too expensive for everyone involved.

An event's lifecycle is long and involves several parties: the invitation designer, the host, and the reception team at the door. Each needs to see certain things — and nothing more.

The solution

One connected path: create the event → design the invitation → add guests → send → track accepts and declines → check guests in by QR scan at the door.

  • Events, details & location
  • Templates & uploaded designs
  • Invitation customization
  • Personal, shared or no QR
  • Manual entry & Excel import
  • Guest details & companions
  • Sending & delivery status
  • Accept / decline tracking
  • Host follow-up links
  • QR scan & check-in links

Engineering

One TypeScript codebase running as four processes — web, worker, WhatsApp bot and migrations — on PostgreSQL 17 with 32 tables, deployed with Docker Compose.

  • Next.js 16
  • React 19
  • TypeScript
  • PostgreSQL 17
  • Drizzle ORM
  • Tailwind CSS 4
  • Zod
  • Sharp + Pango
  • Baileys
  • Docker Compose
  • WhatsApp Cloud API
Strict tenant isolation
Every query is scoped to the workspace from the session; tenant IDs from the browser are never trusted. Covered by a dedicated test.
Race-free check-in
A single conditional UPDATE plus a CHECK constraint. In testing, 30 concurrent scans on a 5-person invite admitted exactly 5.
Background generation at scale
A Postgres-native job queue with SKIP LOCKED and no Redis, de-duplicated jobs, and a render hash per invitation so only what changed is regenerated.
Robust Excel import
10,000 guests in 1.84 s, handling Arabic-Indic digits and invisible marks, catching duplicates and keeping plan limits under concurrency.
Messaging billing that adds up
Two wallets that never go negative, charge-before-send with automatic refunds on failure, and no duplicate sends after a crash.
Secure by design
OWASP-grade scrypt, hashed session tokens, DB-backed rate limits, CSP and HSTS, 128-bit invitation tokens and an audit log of sensitive actions.

Key decisions

  1. Built for service providers

    The core customer runs many events, so the platform is built for managing multiple events under different identities from one account.

  2. Honest sending channels

    Free manual sending; a bot on the merchant's own number with pacing to protect it — no claim to bypass WhatsApp's protections or guarantee against blocking; and an official WhatsApp Cloud API integration that is complete in code and tested with simulated webhooks, with activation awaiting Meta's template approval.

  3. Flexible QR

    Not every event needs a personal QR; offering all three options fits events of very different sizes and styles.
